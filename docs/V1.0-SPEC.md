# Unified Chat V1.0

> Product contract: keep the implementation aligned with the approved four-layer design. Do not introduce CRM, campaign, automation, statistics, or account-management dashboards into the V1 shell.

## Product definition

**Unified Chat** is a local-first desktop communication workspace for multiple isolated chat Profiles.

- No Unified Chat account
- Local first
- Multiple isolated Profiles
- WhatsApp + Telegram in V1
- DeepL first + Google fallback through a Translation Router
- Optional AI only when requested
- Unified Inbox
- Global cross-Profile search
- Profile-scoped Translation Memory
- Clean chat-first interface

## Four layers

```text
                    Unified Chat
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
   Profile Layer    Message Layer    Intelligence Layer
        │                │                │
   多账号隔离        统一聊天          翻译 / AI
        │                │                │
        └────────────────┼────────────────┘
                         ↓
                  Local Data Layer
```

### 1. Profile Layer

A Profile is a complete digital workspace. The user sees a chat account, never a browser profile.

Each Profile owns:

- Session
- Cookies
- Local Storage
- IndexedDB
- Cache
- Window state
- Network settings
- Translation settings
- AI settings

UI names must follow `WhatsApp · Personal`, `WhatsApp · Work`, `WhatsApp · Business`, `Telegram · Personal` rather than `Browser 01`, `Browser 02`, etc.

Profile actions:

- Open directly into its provider workspace
- Restore the last conversation
- Quick switch from the top bar
- `Ctrl+1` through `Ctrl+9`
- Status: Connected / Attention / Disconnected / Not configured
- Health: Session / Network / Messages / Translation
- Backup non-sensitive configuration
- Profile Vault lock/unlock
- Quick Lock: `Ctrl+Shift+L`

### 2. Message Layer

The message layer normalizes provider messages behind a platform-neutral model.

V1 must support:

- Unified Inbox
- All / Unread / Mentions / Favorites / Follow Up
- Cross-Profile conversation list
- Cross-platform message search
- Last conversation restoration
- Original + translated message presentation

The application core must not depend on WhatsApp-specific or Telegram-specific UI concepts.

### 3. Intelligence Layer

Translation is routed, cached, batched, and personalized.

```text
Translation Router
       │
       ├── DeepL
       │
       └── Google fallback
```

Required V1 behavior:

1. Prefer DeepL.
2. Fall back to Google when DeepL is unavailable or fails.
3. Cache repeated translations locally.
4. Batch consecutive short messages before translation.
5. Apply Translation Style: tone, length, and avoid rules.
6. Apply Profile Translation Memory / Personal Dictionary.
7. Apply Conversation Profile overrides.
8. AI is hidden behind `✨` and exposes Reply, Rewrite, Explain, Summarize, Translate.

Settings precedence:

```text
Global Settings
       ↓
Profile Settings
       ↓
Conversation Settings
```

The most specific setting wins.

### 4. Local Data Layer

Local data is the source of truth for application configuration, normalized messages, translation cache, Translation Memory, Profile state, and conversation settings.

Sensitive provider secrets remain in main-process / OS-backed storage and never cross the renderer bridge on reads.

Profile backup must not include login credentials, provider cookies, IndexedDB, or other sensitive browser storage by default.

## Primary navigation

Only:

- Chats
- Profiles
- Search
- Settings

Opening the application should land in Chats.

## Explicit non-goals for V1

Do not add:

- CRM
- Campaigns
- Bulk messaging
- Automation engines
- Contact-management dashboards
- Marketing statistics
- Browser-profile terminology in the user-facing UI
- Security-evasion or abuse-detection bypass features

These constraints are part of the product definition, not optional polish.
